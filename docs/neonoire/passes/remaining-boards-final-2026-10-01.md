## Running order — fixed

Previously, the project stored first boarding followed by coverage: after scene 7 it jumped to 72, then much later returned to 8, and new inserts landed at the project tail. It now follows the current screenplay scene array, with each board quote located in its **own scene**, not the first matching line anywhere in the film. Coverage is interleaved at that beat.

Examples: scene 20 plays **193 → 309 → 194 → 284**; scene 51 **310 → 311**; scene 75 ends with **314**; scene 100 is **320 → 160 → 265 → 260 → 161**, so the held ending remains last. Production numbers may jump; they are identities, not playlist positions. Scenes keep labels such as **25A / 53A / 82A / 99A**, with the cut-scene gaps intact.

The storyboard grid/list, shot list, player, shared view, prompt batches, CSV and print/PDF all use the same scene order. Drag/move works **inside a scene**, not across scene boundaries. Newly added/duplicated shots on a numbered board get a fresh production number, not the source shot's number.

On an existing workspace, normal reads fill still-labelled missing-image slots and backfill production labels. The old default boarding-order array is migrated only when its IDs match that default exactly. A director's custom shot order, script, titles, notes, custom images, deliberate blanks, deletions and additional shots survive. Pending-image titles lose only their machine suffix; original default notes update to the delivery brief only when their saved checksum is unchanged, so instructions added to a waiting card are not wiped. Structural screenplay revisions still require importing the current bundle as a separate copy if an old workspace has an older script or different set of scenes/frames.
